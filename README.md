# Co-op Climb

A friendly **multiplayer co-op platformer for seniors (and everyone)**. Designed for groups of up to 15 players per room. One person hosts on a TV or laptop — everyone else joins by scanning a QR code on their phone.

![players](https://img.shields.io/badge/players-up%20to%2015%20per%20room-brightgreen) ![friendly](https://img.shields.io/badge/design-senior--friendly-blue) ![stack](https://img.shields.io/badge/stack-node%20%2B%20ws%20%2B%20qr-orange)

## How it works

1. **One person** opens the game on a TV or laptop and taps **Start a New Game**.
2. The TV shows **two logos**, a **big room number**, and a **QR code**.
3. **Each player** scans the QR on their phone — the phone connects to that room automatically.
4. **Play together.** Walk, jump, stand on pressure pads, and stack on each other's heads to get everyone to the yellow flag.

The URL in the QR looks like: `https://repo61-production.up.railway.app/?room=1234` — the 4-digit room number is auto-generated by the server.

## Designed for seniors

- **Big, clear touch buttons** on phones: LEFT / JUMP / RIGHT. No joysticks or tiny icons.
- **Gentle physics** — slower movement, lower gravity, generous jumps, big characters.
- **Simple short levels** with wide platforms and clearly-marked pits. No spikes, no timers.
- **Forgiving goal**: only a minority of players need to reach the flag, and you hold for a full 1.5 seconds — nobody gets left behind.
- **High-contrast visuals**, 18–28pt text by default, friendly smiley characters with name tags.
- **One-tap join** via QR. No accounts, no downloads. Kids can help set it up.

## Quick start

```bash
npm install
npm start
```

Open [http://localhost:3000](http://localhost:3000) and tap **Start a New Game**. On the same network, visit the room URL from your phone (or scan the QR code).

For LAN/local testing, set `BASE_URL` so the QR code points to your machine instead of the production URL:

```bash
BASE_URL=http://192.168.1.10:3000 npm start
```

## Controls

### Phone / tablet (players)
Three big buttons at the bottom of the screen: **LEFT**, **JUMP**, **RIGHT**.

### Keyboard (optional, if playing on a laptop)

| Key | Action |
|---|---|
| `A` / `←` | Move left |
| `D` / `→` | Move right |
| `Space` / `W` / `↑` | Jump |

## How co-op works

- **Yellow pads** (pressure plates) open **purple doors** — but only while someone is standing on them. The plate shows `count / required`.
- Some doors need **two pads pressed at once**. Two friends stay, others walk through.
- **Tall walls**: jump on a friend's head to stack up and reach the high pad.
- **Yellow flag**: the level is complete when around 40% of players hold the flag for 1.5 seconds.

## Levels

1. **A Gentle Walk** — basic movement, one tiny hop.
2. **Help Each Other** — one friend stands on a pad, others walk through.
3. **Stand on Shoulders** — stack to reach a high pad nobody can solo-jump.
4. **Two Pads Together** — a door that needs two pads pressed at once.

When the last level is cleared the game celebrates and loops back to Level 1.

## Architecture

```
server.js        Node + ws; per-room authoritative physics at 30 Hz;
                 QR code generation; HTTP API for room creation
levels.js        Level definitions (wide, forgiving, senior-friendly)
public/
  index.html     Landing, Host/TV, and Player screens in one SPA
  game.js        Input, canvas rendering, interpolation, touch controls
  style.css      Large-type, high-contrast, tap-friendly styling
  logos/
    crest.svg       Crest Secondary logo (SVG recreation)
    weeswares.svg   WeesWares logo (SVG recreation)
```

### Rooms

- A **room** is a 4-digit code (`1000`–`9999`) auto-generated when someone taps "Start a New Game."
- Each room has its own physics simulation, players, and level state; rooms are fully independent.
- Rooms are garbage-collected 30 s after the last player leaves (or after 10 min of inactivity).

### Wire protocol (JSON over WebSocket)

Client → server:
```
{type:"join",  role:"host"|"player", roomCode, name, create?}
{type:"input", keys:{left,right,jump}}
{type:"respawn"}                 // manual respawn at last checkpoint
{type:"restart"}                 // reload current level (any player)
{type:"skip"}                    // host-only: jump to next level
```

Server → client:
```
{type:"welcome",  id, role, roomCode, roomUrl, qrDataUrl, level, ...}
{type:"level",    index, level}
{type:"state",    frame, players, entities, goal}
{type:"playerJoin"|"playerLeave", ...}
{type:"error"|"roomFull"|"win"}
```

### HTTP API

- `POST /api/rooms` → `{ code, url }` creates a new room and returns its code + QR URL
- `GET /api/rooms/:code` → basic room info (player count, current level)
- `GET /health` → `{ ok, rooms, players }`

## Replacing the logos with real PNGs

The SVGs in `public/logos/` are faithful recreations built from the original images. To use your actual assets instead, drop the files into `public/logos/` as e.g. `crest.png` and `weeswares.png`, then update the `src` attributes in `public/index.html` (look for `#brand-bar`).

## Configuration

Environment variables (all optional):

| Var | Default | Purpose |
|---|---|---|
| `PORT` | `3000` | HTTP port |
| `BASE_URL` | `https://repo61-production.up.railway.app` | URL that QR codes point to |

Constants in `server.js`:

- `MAX_PLAYERS_PER_ROOM` — hard cap (default 15)
- `TICK_RATE` — physics/broadcast rate (default 30 Hz)
- `GOAL_WIN_RATIO` — fraction of alive players needed at the flag (default 0.4)
- `GOAL_HOLD_TIME` — seconds to hold the flag before advancing (default 1.5)

## Deploying

The app is a single Node.js process. Any Node host works — Railway, Render, Fly, Heroku, a VPS, etc. Set `BASE_URL` to your public URL so QR codes resolve properly.
